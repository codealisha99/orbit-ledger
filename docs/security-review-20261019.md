# Pre-launch security review — 19 October 2026

Scope: OrbitLedger's password/OAuth authentication, browser API bridge, session cookies/JWTs, private WebSocket delivery, financial authorization, database migration, dependency lockfile, tracked secrets, and CI. This is a repository and functional security review, not an independent penetration test or a guarantee against every vulnerability. Production account/order data was not modified as a test.

## Findings and fixes

| Severity     | Finding                                                                                                                                                                                       | Resolution                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| High         | Logout cleared the browser cookie but left its seven-day bearer token usable.                                                                                                                 | Durable session records, a 24-hour lifetime, strict HS256/issuer/audience/purpose/claim validation, and a database session check on protected requests. Logout revokes the current session; Account also offers sign-out on all devices. A user has at most 20 active sessions. Legacy tokens are intentionally rejected.                                                                            |
| High         | Socket authentication accepted general session JWTs and granted a fresh minute irrespective of the ticket's signed deadline. Existing private identity could survive failed reauthentication. | Separate socket audience/purpose, parent session validation, the actual signed expiry, identity clearing before reauthentication, and a fresh parent-session check before each private event. Financial payloads are no longer printed to logs.                                                                                                                                                      |
| High         | An OAuth one-use handoff code was not bound to the browser initiating sign-in.                                                                                                                | A frontend HttpOnly verifier cookie and SHA-256 challenge bind exchange to that browser. Provider-specific state/challenge cookies are Secure in production, time-limited, and cleared on callback. Wrong/missing verifier cannot consume a code. Provider requests have timeouts and require successful responses and verified identity/email. Email matching never automatically links identities. |
| Medium       | Authentication limits could key off a supplied token identity; successful signups escaped the authentication budget. Proxy traffic also shared a gateway address.                             | Authentication IP budgets count successes and failures, with an additional failed-signin account budget. Vercel client IP forwarding is HMAC authenticated and expires after 30 seconds; unsigned/changed/stale assertions are ignored. Production keeps shared Redis counters.                                                                                                                      |
| Medium       | Password hashing blocked the API event loop, six-character passwords were accepted, and bcrypt could silently truncate new passwords.                                                         | Asynchronous bcrypt with cost 12, minimum 12 characters, maximum 72 UTF-8 bytes for new passwords, generic invalid-credential responses, and dummy hashing for unknown/provider-only accounts. Existing passwords continue working. No raw passwords or tokens are logged.                                                                                                                           |
| Medium       | Browser responses lacked a restrictive script policy and anti-framing headers; image optimization allowed arbitrary HTTPS origins.                                                            | Per-request CSP nonces cover Next runtime and the theme script; production disallows unsafe-eval. Frame denial, nosniff, no-referrer and capability restrictions are set. The unused wildcard image allowlist is removed. Inline styles remain allowed for chart/UI compatibility.                                                                                                                   |
| Medium       | GET logout skipped mutation origin checks; the bridge buffered unrestricted bodies and followed redirects.                                                                                    | POST-only logout, exact same-origin mutation checks, 64 KiB streamed JSON limits, a five-second body deadline, path segment validation, no redirect following, and private/no-store responses.                                                                                                                                                                                                       |
| Supply chain | Numerous vulnerable direct/transitive dependency versions and mutable CI action references.                                                                                                   | Compatible dependency updates and explicit fixed-version overrides; frozen lockfile; action commit pins; read-only CI token and job timeout; a dependency audit gate. One build-only advisory has a tested local patch, below.                                                                                                                                                                       |

Financial routes were checked for account ownership, bounded numeric input, parameterized queries and idempotency. Integration tests retain the account-locking, duplicate-execution, overspending, stale-price, and cross-account privacy checks. The candle query's SQL interval is selected from a fixed allowlist; user values are parameters. No new exploitable SQL injection was confirmed in the reviewed paths.

The tracked-file and reachable-history credential scan found placeholder connection strings, with no confirmed live credential in the scanned patterns. This is not evidence that no secret has ever existed elsewhere. Production JWT secret meets the enforced 32-byte minimum. Secrets used for deployment remain outside the repository; the proxy secret is server-only.

## Dependency exception

The final raw audit reports **zero critical and one high advisory**: [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) against `braces@3.0.3`. There is no upstream patched release at review time. It is used by Tailwind/glob/lint build tooling; request bodies are not passed into this parser.

`patches/braces@3.0.3.patch` rejects parser nesting at 128 levels before recursive compilation/stringification. Regression tests exercise both 2,000-level brace and parenthesis inputs through the actual transitive dependency, plus a normal build pattern. Bun applies this patch on install. `bun run security:audit` fails on every other advisory and allows this specific patched advisory only until **19 November 2026**. Upgrade and remove the exception when upstream publishes a fix; do not describe the raw audit as clean.

## Verification

- 16 shared/frontend/poller tests and 24 PostgreSQL/API integration tests pass (165 assertions combined), including session revocation, socket deadline/revoked-parent rejection, OAuth verifier/replay/expiry, signed proxy headers, body limits and financial invariants.
- Type checks, frontend lint, and production builds pass for all four applications.
- Local HTTP smoke tests: signup through the bridge, HttpOnly session cookie, authenticated workspace, logout, replay rejection, cross-origin mutation denial, GET logout rejection, and CSP nonce coverage on all rendered document scripts.
- The production backup was restored to an isolated local PostgreSQL database, then the additive security migration applied successfully. Restored state contains six users and five active positions. The migration creates session records and adds an OAuth challenge column; it does not rewrite balances, positions or history.
- Browser interaction/visual regression was not exercised in this security pass. Actual Google/GitHub provider round trips remain unverified because those providers are disabled in this deployment. Functional tests cover the local exchange/security contracts.

## Deployment and remaining limitations

Deploy API migration/backend and WebSocket before the frontend. WebSocket now needs the same application database and JWT secret. Set a separate, shared `API_PROXY_SECRET` on backend and Vercel production; never use a `NEXT_PUBLIC_` prefix. The frontend checks the API's revocable-session capability before sending bridged requests. Older cookies require sign-in again. Keep the additive schema when rolling back and never restore the previous stateless authentication implementation as a security rollback.

This is a paper-trading portfolio MVP. Password email ownership verification and self-service recovery are still absent; users cannot recover forgotten password accounts through the app. Do not present those capabilities as complete or accept real funds. Real provider sign-in requires configured credentials and an end-to-end provider check. Hosting-account access/MFA, database roles, backup schedules, alert delivery, infrastructure incident response, and representative load/abuse testing are operational work outside this code review. WebSocket input/frame/buffer/connection limits reduce resource exhaustion, but application limits do not replace platform DDoS controls.

Security rationale: [OWASP session management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), [Next.js nonce-based CSP](https://nextjs.org/docs/app/guides/content-security-policy), and [Vercel trusted forwarding headers](https://vercel.com/docs/headers/request-headers).
