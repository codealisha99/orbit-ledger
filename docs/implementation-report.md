# Trading and Dashboard implementation report

Local verification date: 18 October 2026. Implementation follows [the product-quality plan](product-quality-plan.md). Deployment, production data recovery, provider credentials, and representative staging load remain external release gates; see [the runbook](release-runbook.md).

Follow-up: the production service-version mismatch and its correction are documented in [the deployment incident](deployment-incident-20261018.md). The subsequent landing-page rebuild includes an interactive illustrative trading scenario, chart-draw and orbital motion, responsive layouts, FAQ, and motion controls. Current automated coverage is 29 tests / 95 assertions.

## Delivered

- Shared black/blue application shell with light theme, compact market summary, a larger chart, separate candle interval/range controls, saved URL preferences and Back/Forward behavior, a focused paper trade ticket, and responsive chart → ticket → account flow.
- Dashboard backed by an authoritative account snapshot: available cash, reserved collateral, signed gross open P&L, equity, actual positions, exposure/risk, grouped completed-position performance, recent executions, and genuine recorded equity valuations. Stale/unknown values remain unavailable.
- Database-authoritative account mutations under a per-account PostgreSQL advisory transaction lock. Separate remaining exposure, collateral, allocated costs, execution receipts, account versions, idempotency replay, and a transactional outbox. Additional collateral leaves quantity unchanged; partial exits conserve remaining exposure/collateral/costs; fractional effective leverage drives liquidation. Isolated gap losses do not consume unrelated cash.
- Safe read-only position restoration, consistent configured new-account allocation, source timestamps in milliseconds, common fresh-quote validation across manual and risk execution, and fresh trigger revalidation inside the transaction.
- Chart requests scoped and aborted by symbol/interval/range; one chart instance survives theme/style changes; fit controls use all available requested bars. OHLC uses display prices and the actual hovered bar. Genuine exchange prints drive candles and a distinct pauseable/deduplicated market tape. Historical coverage, unavailable combinations, UTC dates, weekly boundaries, rollover repair, and bounded backfill jobs are explicit.
- Actual positions, searchable/filterable/sortable cursor-paginated execution history, full-filter CSV exports, lifecycle receipts, persisted private activity, and accessible native mutation/receipt dialogs. Gross, allocated entry costs, exit fees, and net results are distinguished. Unknown legacy fees do not become invented net P&L.
- One managed market/account WebSocket client with heartbeat, reconnect jitter, subscription cleanup, bounded prints, private short-lived tickets, and reconnect reconciliation. Durable event replay and shared visible-account polling recover missed updates; background tabs pause polling. Structured HTTP errors preserve sessions during service failures and keep ambiguous requests recoverable with their original key and account identity.
- HttpOnly same-origin session proxy, one-use expiring OAuth handoff, verified provider email, explicit provider availability, no automatic linking by email, labeled/autocompleted auth fields, and honest virtual-funds landing copy.
- Safe integer money/price representation beyond the old 32-bit ceiling, migration review flags for ambiguous legacy exposure, bounded equity retention, opt-in legacy snapshot retention, durable SQLite ingestion spool, Kafka commits after database writes, symbol-scoped trade deduplication, readiness/lag diagnostics, service-specific deploy configs, CI, and a recovery/rollout runbook.

## Verification completed

- All four applications pass TypeScript checks. Frontend ESLint is configured and passes. All four applications build; the production frontend uses Next.js 15.5.28.
- **25 automated tests / 88 assertions passed** across shared financial/time rules, ingestion durability, PostgreSQL mutation/concurrency/restart/risk scenarios, HTTP authentication/idempotency/privacy/query validation, and one-use/expired OAuth codes.
- Fresh-database Prisma migration deployment passed. Schema diff against the migrated database reported **no differences**.
- A separate legacy-fixture migration preserved four active orders and the original 500,000-cent cash balance. Plain, partial-only, and added-only exposure mapped correctly; the ambiguous partial-plus-added position was flagged for review. Existing fee history remained explicitly unverified.
- A real API process restart preserved the local browser account's 489,950-cent cash balance and its 10,000-cent reserved position.
- The collaborative browser exercised signup → open → add $50 collateral → partial close → final close → receipt/history → Dashboard against an isolated local database and live Binance public data. Quantity remained unchanged on adding collateral, then halved with a 50% exit. Final equity/cash was **$4,997.48**, reconciled to **−$1.03 gross P&L − $0.75 entry/addition costs − $0.74 exit fees = −$2.52 net**. The two exits count as **one** completed parent position. Native dialog keyboard focus trapping and Escape were checked.
- BTC/ETH/SOL each returned **169 hourly bars for 1W** and **127 four-hour bars for 3W**. All-history weekly requests returned hundreds of bars with actual coverage; SOL's listing constrains its history. Range selection, line/candle switching, and light/dark changes were exercised. The backfill includes the first intersecting Monday bar.
- The market tape contained 100 genuine Binance prints with exchange time, quantity, price, and source. Account summary reads observed in the production-build browser took 7–11 ms; nine range requests took 9–22 ms locally. These are development-machine observations, not staging p95 or production commitments.
- Layout checks at 1440×900, 1280×800, 768×1024, and 375/390px found no page overflow; the desktop ticket submit action stayed visible. Final collaborative screenshots and DOM checks passed for the production build. The mobile equity chart uses its actual available width so labels remain readable. Seven genuine equity valuations were available in the local account. Measured primary-button contrast was 5.33:1 dark / 6.01:1 light, muted text 7.97:1 / 6.22:1, and control borders 3.16:1 / 3.31:1. Actual 200% browser zoom and a full screen-reader audit remain staging gates.

## Dependency health

The initial `bun audit --json` reported 3 critical, 62 high, 85 moderate, and 8 low advisory records. Removing unused Axios and applying compatible framework/server/WebSocket/tooling updates reduced this to **0 critical, 34 high, 47 moderate, and 3 low advisory records** in the last full audit. Counts are advisory records, not distinct exploitable runtime issues; they include transitive tooling dependencies. The remaining inventory includes Prisma CLI/development dependencies and CSS/build dependencies (Hono, fast-uri, brace-expansion, browserslist, PostCSS, and others). Do not label the release security-cleared on this basis. Triage reachability and apply verified dependency fixes before production rollout; record accepted exceptions explicitly. No unrelated major Next.js upgrade is included.
